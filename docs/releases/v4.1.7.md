# Operon Studio 4.1.7

- Remote environment control: `operon_environments` and
  `operon_environments_prepare` accept `profile_id`, so an agent can inspect and
  prepare isolated environments on a selected server. The desktop status panel
  gains a per-server **远程环境** section with load and prepare actions.
- Dependency repair can be requested together with environment preparation
  (`dependencies=True`) and runs on the target server.
- Environment installs bootstrap `setuptools>=68` and `wheel` before the declared
  requirements, fixing `No module named 'pkg_resources'` in `openmm81`.
- Failed installs keep evidence: the staging tree is renamed to
  `.failed-<name>-<id>` instead of being deleted, so errors and logs stay
  available for inspection.
- Environment progress now includes the running PID and command, so a long
  conda download or a stuck build is visible from MCP and the desktop.
- Server-side environment RPC (`environments`, `environments_prepare`,
  `environments_log`) uses a 300-second client timeout; an older server answers
  `Unknown remote operation`, which the desktop reports without dropping the
  connection.
- `docs/agent_environment_repair.md` gains an OpenMM/PDBFixer section.
- Requires operator library 8.0.6 or newer; the built-in library is 8.0.6.
