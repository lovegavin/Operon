# Operon Studio 4.0.7

Application 4.0.7 keeps the bundled operator library **8.0.2** and the wire
protocol v3 / SDK 3.7 unchanged. It is a correctness and stability release.

## Fixes

- Remote admission failures now mark the local job **failed** with the
  admission reason and error, instead of leaving the run history stuck in
  `queued`. A resource-infeasible job shows actionable guidance.
- Readiness is validated against the current graph digest. Editing the canvas
  after a readiness check now yields `environment_stale` and asks you to check
  the run conditions again.
- Disabling memory management no longer reserves the entire host pool; it
  disables the per-run memory ceiling while preserving CPU exclusivity.
- Remote prepare verifies the saved SSH connection only at launch, so offline
  workflow preparation, validation, and bundle export still work.
- The `/api/remote` status response omits job history, setup logs, and connection
  payloads; polling no longer grows with run history.

## Verification

- Focused backend suite: 45 passed (admission, coordinator reconciliation,
  readiness, remote prepare/launch).
- No additional Windows install test was run for this release.

## Upgrade

Install 4.0.7 over 4.0.x normally. Setup creates a new profile and does not move
an old `%USERPROFILE%\.operon\profiles\<old-id>\workspace`; copy any data you
still need into `<install root>\workspace`. The workspace is preserved on
uninstall.
