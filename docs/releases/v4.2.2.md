# Operon Studio 4.2.2

Operon Studio 4.2.2 adds backend-owned task folders and workspace writes, fixes
file-artifact downloads, and ships operator library **8.0.9** as both the bundled
and the minimum supported library.

## Task folders and backend writes

Agents can now create a task skeleton and write reports without relying on the
host shell's permissions:

```text
operon_task(base_dir="task1")                      # input, results, reports, figures
operon_task(base_dir="project/task2", folders=["input", "reports"])
operon_write_text(path="task1/reports/summary.md", content="# Summary\n")
```

HTTP equivalents (edit scope) are `POST /api/v1/tasks` and
`POST /api/v1/workspace/files`; the capabilities `task-scaffolding` and
`workspace-files` advertise them. The service performs the write, which matters
when a sandboxed shell runs below the workspace's integrity level.

Safety rules are enforced in the backend: paths are workspace-relative; absolute
paths, drive letters, `..`, empty segments, symbolic links and internal roots
(`.studio`, `.operon`, `.admission`) are rejected. Existing files require
`overwrite=true`; writes are UTF-8 and limited to 10 MiB; empty parent folders are
created. These tools do not grant shell access or change execution authority.

## File artifacts download as files

`GET /api/v1/jobs/<job>/artifacts/<id>/file` previously returned the artifact's
cached `files.json` manifest when `role` was omitted, so clients saved
`<id>_files.json` instead of the CSV. The endpoint now resolves the exported file
(default `data`, otherwise the first role) and streams it. `?role=<name>` is
unchanged, unknown roles still fail, and external inputs are still refused.

This also repairs downloads for files exported by earlier versions; job records
are not rewritten.

## Wait and remote diagnostics

- `operon_job(wait_seconds=...)` accepts up to 120 seconds and returns
  `wait_timed_out: true` when the window closes, instead of an error.
- A missing SSH input environment now explains that the server profile may be
  missing or disconnected and points at `operon remote-status` /
  `operon remote-ensure`.

## Operator library 8.0.9

- `interface_alanine_scan` marks Gly→Ala mutations with `flag: "gly_to_ala"`,
  `excluded_reason` and `excluded_from_ranking`; `quality.gly_to_ala_excluded`
  counts them and per-residue warnings explain the exclusion. The 1361.856 and
  309.699 kJ/mol outliers from the 4.2.0 reports remain visible but are excluded
  from ranking by explicit fields.
- `interface_alanine_scan` and `interface_mmgbsa_delta` documents gained a
  "Scientific limitations" section: single-point estimates, no entropy, ensemble
  or calibration, manual Gly→Ala review, copy reproducibility and cross-version
  comparability warnings.
- The descriptor index was refreshed. `code_sha` covers the provider source tree,
  so every built-in descriptor hash changes together; saved workflow values and
  pins are unaffected.

## Compatibility

- **Requires operator library 8.0.9 or newer.** 4.2.2 refuses older libraries
  with an explicit version error instead of importing them.
- Bundled library: 8.0.9 (7 packages, 1,171 descriptors, 1,063 operators,
  108 Readers, 79 routes).
- Existing workspaces remain valid; `workspace`, `environments` and profile data
  survive upgrades and uninstalls.
- Application-side fixes from 4.2.1 (artifact default role, wait semantics, SSH
  hint) are included.

## Validation

See `ACCEPTANCE.md` and `VERIFICATION.json` in the release assets. The focused
backend suite, the frontend suite, a Windows install over 4.2.1 and an HTTP bridge
probe of the new task tools are recorded there. Windows uninstall, remote server
deployment and the full Windows Python suite were not part of this release run.
