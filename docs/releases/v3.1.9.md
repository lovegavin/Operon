# Operon Studio 3.1.9

This release fixes desktop startup and installer path selection, and makes route
collection import a single-file action.

## Desktop startup

- The host now derives the `OPERON_READY ` and `OPERON_STARTUP_ERROR ` JSON
  offsets from the prefixes themselves. The shorter Operon prefix previously
  left the leading `:` in the JSON document, so a successful backend start
  surfaced as `JsonReaderException` and the window closed.
- A backend startup failure is reported with the server's message instead of a
  malformed-JSON parse error.

## Installer and uninstaller

- The destination picker is available in both install and uninstall mode. The
  uninstaller no longer requires a fixed path or a command-line argument.
- Selecting a parent folder fills in `Operon Studio` automatically, and the
  resolved destination is shown for confirmation before installation starts.
- The uninstall confirmation names the exact installation directory.
- Duplicate autostart, Start Menu and pinned-shortcut entries left by the
  product rename are removed.

## Route and operator library import

- The ordinary operator library accepts only `.whl` and
  `.operon-library.zip`. Other zip files are rejected instead of being treated
  as operator libraries.
- A route collection is uploaded as one `.zip`. Every `.operon.zip` below a
  `route/` or `routes/` folder is imported, saved and registered automatically;
  nested wrapper folders are supported and no per-file selection is required.
- Unsafe paths, encrypted members, oversized members, empty collections and
  traversal entries are rejected.
- `docs/library_import_compatibility.md` now documents these rules; the old
  manual extraction instructions and compatibility aliases are gone.
