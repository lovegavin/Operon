## Linux real delivery

System Python 3.12.3 (through an independent venv) and Conda Python 3.13.5 were
prepared without editing system Python or the existing Conda base. Both completed
the owned numerical route and exported standalone execution after moving to a
path with spaces. The Conda route also ran actual xz compression/decompression.
Developer Python/Operon paths were removed from the standalone launch environment.

The final server archive was uploaded, SHA256 checked and installed through its
own `install.sh` into a separate prefix. The installed CLI reports `Operon 5.3.0`.
Its installed application code then built another portable package against the
previously verified Conda environment. That moved package completed with exit 0.

Network boundary: official Python runtime archives used a local mirror after the
server's download stalled. The final server installation used downloaded official
Linux wheel files with `--wheel-dir` after a PyPI transfer stalled. This verifies
the offline installation path; it does not claim the stalled network paths passed.

## Windows installed interaction

RC1 installed and opened through the shortcut, but its imported script canvas
failed frozen dependency-list validation. It was not published. RC2 restores
JSON arrays at the immutable RunPlan/script validator boundary, preserving strict
SDK input validation. Ten focused snapshot/package/actual script pool-export
tests and one actual Application preparation test passed. The moved launcher
produced the expected source values and two scaled CSV branches.

RC1 also carried stale application-version text in its runtime receipt despite
having the current code. RC2 refreshes this metadata; packaging now rejects a
stale receipt. Independent RC2 installed interaction remains pending; do not
promote the draft before that gate passes.

## Scope limits

Automatic native canvas routes currently use one host. Multi-host/Slurm remain
experimental. Arbitrary unowned system executables, hidden dynamic resources,
GPU drivers and external services are not promised as self-contained exports.
System-R acquisition is implemented but the real R acceptance here used a private
Windows R installation; it is not a Linux system-R installation claim.
