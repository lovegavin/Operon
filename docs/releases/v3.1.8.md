# Operon Studio 3.1.8

Operon Studio 3.1.8 is the first release after the complete product rename from
the earlier internal name. There is no compatibility alias: the Python package,
distribution, command line, MCP tools, provider IDs, installer, registry entries
and bundled Python runtime all use the Operon name.

## Naming

- Python distribution `operon-studio`, import package `operon`, SDK `operon_sdk`.
- CLI `operon` and `python -m operon`; the old command name is no longer shipped.
- MCP tools and resources use the `operon_*` prefix.
- Built-in provider packages and operator IDs use `operon-*`.
- Windows projects are `OperonStudio.csproj` and `OperonSetup.csproj`; the
  installer writes `Operon Studio` shortcuts, `OperonStudio-*` uninstall keys
  and `operon-install.json` receipts.
- Profiles, runtime metadata, server receipts, environment variables, headers,
  named pipes and protocol identifiers use Operon names.

Workflows or external plugins that refer to the old provider IDs must be updated
to the renamed `operon-*` IDs. Saved graph shapes, parameter values and execution
semantics are unchanged.

## Operator library

The bundled library is `2026.11.8.1` with the renamed provider packages. The
catalog and indexes are regenerated from the factory seed; the operator and
Reader implementations are otherwise the 3.1.7 set.

## Windows lifecycle

The Windows host keeps the 3.1.7 tray behavior: closing the window hides Operon
Studio, and **完全退出（停止 Python）** flushes the draft, stops the managed
backend and closes the Job Object. The uninstaller is selected by filename,
confirms before terminating Operon/Python processes, removes shortcuts,
autostart entries, pinned taskbar links and the registry key, and deletes the
installation root.

## Validation

Validation is recorded in `ACCEPTANCE.md`, `VERIFICATION.json` and
`CI-RESULTS.json` beside the release assets.
