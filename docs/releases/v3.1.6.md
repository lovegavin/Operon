# Operon Studio 3.1.6

This maintenance release repairs remote-session recovery and diagnostics, keeps
unavailable historical generations from being mistaken for compatible ones, and
makes the existing Agent environment-preparation permission explicit. It also
adds a real FASTA → FastaReader → Kabat CDR contract regression. The independent
operator library, SDK protocol, scientific dependency versions and frozen
workflow values are unchanged.

## Remote service recovery

An installed-server connection now respects the real list-shaped remote status
when restoring key/agent authentication instead of treating it as a dictionary.
This fixes the confirmed `AttributeError` in `RemoteManager.ensure()` and keeps
the requested profile isolated from other connected servers.

A live SSH bridge no longer assumes its RPC daemon exists forever. If the daemon
idle-exits or its Unix socket disappears before a request is transmitted, the
bridge serializes recovery through the existing workspace startup lock and
retries the same request once. The request keeps its original correlation ID.
A failure after any request bytes may have been sent is reported as an unknown
outcome and is never replayed. This preserves job request IDs, installation
idempotency, pool jobs and leases.

Failures use stable machine-readable codes and structured `details`
(`phase`, `request_id`, `trace_id`, `path`, `errno`, `retryable`,
`recovery_attempted`). Bridge and daemon-dispatch diagnostics are written to
bounded `.studio/remote/bridge.events.jsonl` and
`.studio/remote/dispatch.events.jsonl`; secret-shaped text is redacted. Existing
`error`/`code`/`node_id` fields remain compatible with older peers.

The original private VHH report did not include its graph or complete remote
traceback, so this release does not claim that the author's exact host incident
was reproduced. The confirmed transport and validation defects are covered by
focused regressions.

## Historical generations

Missing or unreadable retained generation files are classified as
`pin_generation_missing`/`pin_generation_unreadable`. They are never accepted or
silently repinned. A broken unrelated server no longer blocks a workflow
explicitly targeted at local or another host; an explicit unavailable target
remains blocked.

## Agent installation permission

The Agent connection panel now has a default-off **Allow the Agent to install
or repair operator packages and environments** option. Selected, it adds the
existing `--allow-plugins` capability to the copied MCP configuration and
preserves the configured interpreter, workspace, profile and execution
arguments. It does not grant canvas edit or job submission. Existing connected
clients must reconnect before gaining the capability. Missing permission returns
an actionable 403 and `check-environment` remains available with read-only
context permission.

## FASTA and CDR contracts

A regression builds a protein FASTA input through the real `FastaReader` into
`antibody_cdr_kabat`; the Reader's declared representation, alphabet and
missing-code metadata satisfy the downstream contract without hand-edited graph
information. A numeric CSV edge is rejected rather than bypassing format
validation, and ambiguous sources name the available Reader candidates.

## Packages and validation

- `Operon_Setup.exe`: Windows installer with the existing private management Python.
- `Operon-3.1.6-Server.zip`: Linux installer, application wheel and unchanged factory seed.
- `operon_studio-3.1.6-py3-none-any.whl`: application wheel for existing deployments.

Release attachments record the focused tests and packaged/native acceptance for
these exact bytes. Source tests do not imply that every scientific operator or
the original private VHH workflow was run.
