# Operon Studio 4.0.9

Application 4.0.9 keeps the bundled operator library **8.0.3** and the wire
protocol v3 / SDK 3.7 unchanged. It fixes a shared-pool upgrade deadlock.

## Shared-pool upgrade

- A forced server upgrade now tells the new daemon to close all existing
  workspace sessions before it registers.
- Registration also prunes sessions whose owner process has exited, so a
  workspace left by a killed 4.0.4 process no longer blocks the new server.
- A normal upgrade is still guarded: active work aborts the upgrade without
  closing live clients. Only the explicit force path clears sessions.

> Correction: 4.0.9 skipped re-applying stale remote pins but did not remove
> pins already present on the canvas. Use 4.0.10 for the complete fix.

## Remote runs and status

- Remote submissions no longer copy stale canvas plugin-lock entries over the
  implementation pins refreshed by the selected server; local runs still retain
  their original pins as evidence.
- MCP operon_remote_status now reads /api/remote/summary, returning build and
  library-check facts instead of the full catalog payload.

## Verification

- Shared-pool tests: 3 passed (dead-owner pruning, live-client blocking,
  forced re-registration).
- Pool + remote upgrade tests: 27 passed.
- Managed pool + provisioning + retirement tests: 32 passed, 3 skipped.
- No frontend code changed. No full Windows Python suite was run.

## Upgrade

Install 4.0.9 over 4.0.8 normally. The application version changes; the bundled
library and protocol do not. Existing workspaces and results are preserved.
