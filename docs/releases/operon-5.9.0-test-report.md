# Operon Studio 5.9.0 test report

Date: 2026-11-25. Application: 5.9.0. Library: main-v2.0.0.
Host: WSL Ubuntu-24.04 build host (no isolated environments installed, no remote
server upgraded in this release).

## What was verified

The release makes ports the only transport for run data. Verification therefore
targets three things: the declarations moved, the catalog still builds, and the
existing tests did not regress beyond the environment-gated failures that already
existed on the base commit.

The packaged descriptor index was stale on the base commit: it had last been
regenerated at `60ae512d6`, so every bundled operator and reader load raised
`ValueError: Implementation code hash mismatch`. Commit `397eddfd9` rebuilt the
index (2365 `code_sha` lines, package-level hash churn) and the four failing
tests moved on to their real cause (missing isolated environments).

## Migration checks

- No shipped route uses a converted operator (`scripts/port_contract_inventory.py`
  records the operator list; a route scan over `library/seed/routes` returns 0
  matches).
- `library/seed/routes/msa_analysis/task.yaml` chains `msa_trim` ->
  `export_results` with `format: fasta`; the export renders the alignment from the
  form, covered by the export test above.
- The old data path parameters remain declared with an empty default and
  `x-operon-path: workflow`, so direct API calls and existing tests keep working
  while a graph that supplies the port does not look incomplete.

## Limitations

- The release was not deployed to a remote server; verification is local.
- 97 environment-gated failures remain in the affected suite because the build
  host has no isolated operator environments. They are identical to the base
  commit and unrelated to the port change.
- Making the path parameters optional rather than deleted is deliberate: 170 test
  references and several shipped route templates still set them. Removing them is
  a follow-up that needs its own migration.
