# Operon Studio 4.0.8

Application 4.0.8 keeps the bundled operator library **8.0.3** and the wire
protocol v3 / SDK 3.7 unchanged. It completes the installer cleanup and local
input staging work.

## Installer

- Setup accepts a non-empty folder that is not an existing Operon installation.
  Unrelated files are preserved; only Operon-owned versions, shortcuts and
  registry entries are removed.
- Uninstall disconnects every reachable local MCP client before terminating
  Operon processes, including when the frontend has already exited.
- After a failed install, Setup offers **强制重装** so old Operon processes and
  version files can be cleared without deleting the workspace or foreign files.

## Local input for remote runs

- The Inspector now explains that a selected local file is copied to the Operon
  data directory and uploaded to the selected remote workspace at run time.
- Legacy `source.location: "local"` / `"ssh"` values are normalized to the
  current execution-target object instead of being rejected.

## Verification

- Frontend: 177 tests passed across 30 files.
- Backend execution-target compatibility test: 1 passed. The broader execution
  suite was not rerun because generated operator documentation is absent from
  this source-only checkout (15 fixture errors).
- Installer: 0 warnings, 0 errors.
- Windows foreign-directory install/uninstall: passed;  survived and
  the Operon child directory was removed.
- No full Windows Python suite was run.

## Upgrade

Install 4.0.8 over 4.0.x normally. Setup keeps the existing workspace and
profile; it does not migrate an old profile workspace to the new installation
root. Uninstall preserves the workspace.
