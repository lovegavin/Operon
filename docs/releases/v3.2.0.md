# Operon Studio 3.2.0

This release makes an installed server a complete, verifiable copy of the
desktop application and its operator library. It fixes the canvas error
`selected environment is unavailable` when a managed server still held an older
operator implementation under the same operator identifier.

## Build identity

The application, the bundled library and the installed catalog now produce one
deterministic `build_id`. Desktop and server derive it from the same source
archive and library definition, so a routine SSH connection can prove that both
sides are identical before reusing a cached catalog.

Each managed installation records the identity in `server.json` and in the
environment receipt. A connection to an older managed installation fails with
the stable `stale_build` code instead of silently reusing its catalog. The
server panel opens the existing maintenance flow and offers **安装 / 升级服务端**.

## Full operator-library replacement

The managed installer now installs the library carried by the uploaded
application as one bundle. It replaces the complete built-in provider set; it
does not merge new wheels into an older registry and it does not keep a stale
provider that disappeared from the new library. Existing source-edit protection
is bypassed only for this explicit managed replacement.

`library_manifest` reports the installed build and the per-operator
implementation digest. `library_check` reports `changed_count` and
`replacement_required`, and the remote library panel distinguishes
`implementation_changed` from a merely missing package.

## Execution pins

When the server build changes, `RemoteManager.prepare()` replaces a pin whose
operator implementation changed and records the previous pin as
`migrated_from`. A node whose operator is genuinely gone remains unavailable
with its operator ID; it is never silently deleted or rewritten.

## Packaging

The independent library is versioned `2026.11.7.1`; the application is `3.2.0`.
The server asset is built from the matching wheels and keeps the 3.1.6 layout:
`Operon-3.2.0-Server.zip`, executable `install.sh`, `SHA256SUMS`, the script
pipeline example and the release documentation. Published 3.1.6 artifacts are
unchanged.

This build publishes the Linux server asset, the application wheel and the
Linux library bundle. The Windows desktop installer is produced by the Windows
packaging job and is not part of this artifact set.
