# Operon Studio 4.1.5

Environment preparation is now observable and no longer races a client timeout.

## Isolated environment preparation

- `POST /v1/environments/prepare` starts the work and returns immediately; the
  desktop and MCP no longer block for the whole conda transaction.
- The client no longer applies a request timeout to environment preparation.
  A first openmm81 install downloads the conda-forge repodata (about 490 MB on
  Windows) and extracts many packages, which legitimately takes tens of
  minutes on a slow link.
- Each environment writes `.operon-environment-progress` with the current
  phase (`creating`, `installing`, `probing`, `committing`, `ready`,
  `failed`), transferred bytes, file count, and update time. The file is
  refreshed every two seconds while micromamba runs, so an agent can tell
  "still installing" from "failed".

## Runtime dependencies

The bundled portable runtime now installs `requirements-runtime.txt`
(`scipy`, `pandas`, `matplotlib`, `statsmodels`, and the rest of the base
scientific stack) instead of shipping only the application package. The
release gate imports these packages from the packaged interpreter, so a
runtime with a stale or incomplete `site-packages` fails the build instead of
reaching users.

## Runtime status panel

The library footer has a new "Runtime status" dialog:

- local shared-pool instance: version, implementation, address, pid, closing
  state, registered workspaces, and active jobs;
- active jobs across workspaces;
- isolated environment preparation: status, phase, transferred size, file
  count, error and log tail;
- server connections with application version and library refresh state.

The panel refreshes every three seconds from local state; it never blocks on
the network.

## Notes

- The application still supports operator library 8.0.6 and newer only.
- A remote shared pool keeps refusing `pool.retire` while any registered
  workspace has queued, preparing, running, or recovery-required jobs; the new
  panel makes that state visible instead of surfacing a bare client timeout.
