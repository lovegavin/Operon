# Operon Studio 4.0.0

Operon Studio 4.0.0 ships the Operon 8.0.1 built-in operator library and targets
the 8.0.0+ library generation.

## Operator library

- Built-in library: 2026.11.8.1 replaced by library 8.0.1.
- 1,063 operators, 108 Readers, seven provider packages.
- 79 built-in route templates from the 8.0.1 library.
- `.operon-library.zip` remains the only accepted operator-library archive.
- Route collections are uploaded as one `.zip`; every `route/` or `routes/`
  member ending in `.operon.zip` is imported and registered automatically.
- Route imports are isolated: compatible routes are kept and incompatible ones
  are reported without aborting the batch.

## Startup and uninstall

- Fixed the desktop startup parser after the shorter `OPERON_READY ` prefix.
- The installed uninstaller always prompts to disconnect DSH/MCP before
  terminating Operon processes.
- The installer uses an editable destination and resolves the default
  `Operon Studio` folder for the UI; command-line `--install-dir` is exact.

## Compatibility

- No biopipe compatibility alias, legacy module, old bundle path or old file
  format is supported.
- Operon Studio 4.0.0 requires an 8.0.0-or-newer built-in library.

## Verification

- Focused Python suite: 65 passed, 2 skipped.
- Frontend: 179 tests passed; `tsc -b` and Vite build pass.
- 8.0.1 route collection: 79 routes imported and registered.
- Windows and remote acceptance for this build are recorded in the release
  metadata.


## Protocol and SDK

- The wire protocol remains protocol 3; the SDK is 3.7.0. There is no new wire
  major in 4.0.0.
- The bundled library is 8.0.1 and requires Operon 8.0.0 or newer.
- New declarations use `protocol_revision: "3.7"` and explicit
  `data_formats.inputs`/`outputs`.
- The complete extension guide is [library extension forms](../library_extensions.md).
