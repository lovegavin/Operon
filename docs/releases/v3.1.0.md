# Operon 3.1.0 — shared resource pool and reliable execution

## Downloads

- **Windows:** `Operon_Setup.exe`, including the lightweight management runtime.
- **Linux server:** `Operon-3.1.0-Server.zip`, including the application wheel,
  command-line installer and pool administration guides.
- `SHA256SUMS.txt` and `VERIFICATION.md` describe exact artifacts and evidence.

This is an application release. The factory operator library is unchanged and
continues to be maintained separately on `library/main`. Application maintenance
uses `fix/3.0.1-installation`; `main` remains retained but inactive.

## Execution engine

The existing scheduler remains the default. Administrators can explicitly start
one resource-pool service for multiple trusted workspaces and SSH clients:

```bash
python3 -m operon pool serve --config pool.json
```

See [pool configuration and ordinary-client routing](../design/pool_service.md).
All participating tasks share one CPU/RAM accounting authority. Submission keys
are durably claimed, lost responses do not trigger another launch, and client
disconnects do not cancel running work. Confirmed process-tree exit gates resource
release. Sessions can reconnect after a pool restart and live workers can be
adopted without restarting the scientific calculation.

The ordinary execution service retains placement, uploads, stage boundaries,
frozen parameters and result exchange in pool mode. Transfer buffers use the
same pool ledger. An unavailable pool fails explicitly rather than falling back
to an independent local allocator. CLI, API, MCP and SSH use the shared service
boundary. Engine status and durable events are available for inspection.

## Optional verified stage cache

Set `runtime.execution.cache` to `"verified"` to request reuse. Each participating
operator and Reader must explicitly declare a valid optional `resources.cache`
contract. Inputs, frozen values, implementation locks, execution semantics,
selected interpreter and dependency file contents contribute to identity;
artifacts are verified again before reuse. Old undeclared operators run normally.
See [authoring and eligibility](../stage_cache.md).

The cache field extends the existing v3/3.7 resources object without a base
protocol bump. Use Operon 3.1.0 or newer on the execution host for this feature.
No library-wide deterministic declarations or operator rewrites are included.

## Integration repairs and branding

- Selected scientific interpreter identity is used for maintenance exclusion;
  the desktop's management interpreter is not substituted.
- Remote durable-claim failures refuse launch; transfer ownership and capacity
  use the shared pool's authoritative state.
- The Studio memory ceiling correctly reads pool capacity.
- Hot-installed operators become visible through the current catalog generation.
- Early worker/preparation errors retain a console log.
- Linux bundle installation references the actual included wheel filenames;
  the build rejects application/source version mismatches.
- Remaining visible application labels and suggested agent commands use Operon;
  `python -m operon` is supported. Historical Python imports, MCP tool IDs,
  schemas and stored data remain compatible.

## Validation and limits

Windows regression/product tests and real Linux two-client SSH, file reuse,
numeric workers, cancellation, reconnect and actual pool process crash/restart
were exercised. Consult [the acceptance record](../design/server_engine_acceptance.md)
and the attached `VERIFICATION.md` for counts and package-specific checks.

The pool is for trusted clients under one OS account, not hostile multi-tenancy.
Direct clients require shared workspace storage; remote access uses a co-located
SSH service. Environment repair uses a mutex, not immutable generations. R,
external tools, isolated targets and dependency extras are currently ineligible
for verified cache reuse. Production Reader streaming, systemd operational
acceptance and long-running scientific elastic-resize benchmarks remain separate
work; this release does not claim those roadmap items are complete.
