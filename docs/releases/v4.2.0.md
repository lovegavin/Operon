# Operon Studio 4.2.0

Operon Studio 4.2.0 ships the 8.0.8 operator library and changes where a run
writes its results.

## Task folders

Results are no longer hidden inside `.studio`. A run stores its outputs next to
the data it analysed:

```text
<workspace>/<task>/
  input/            original data for this task
  results/<job-id>/ artefacts, run summary and logs for that job
```

`.studio/jobs/<job-id>/` keeps only the launcher state (job.json, console log,
launch events). The graph's `base_dir` selects the task folder; a job started
without one writes under `<workspace>/results/<job-id>`. Existing documents are
not moved: their `base_dir` stays exactly as saved, so old jobs keep working and
new runs use the task folder.

## Operator library 8.0.8

- 7 packages, 1,171 descriptors, 1,063 operators, 108 Readers.
- OpenMM isolated environment fixes: `setuptools<81` bootstrap and
  `pkg_resources` probing.
- Interface alanine-scan and MM/GBSA protocol metadata updates from the library
  release.

## Compatibility

- Requires operator library 8.0.6 or newer; this build bundles 8.0.8.
- Existing workflows, saved values and plugin locks are preserved.
- Remote servers can be upgraded through the desktop "Install / upgrade server"
  action, which retires the old pool before the replacement.

## Validation

- Frontend build and full Vitest suite.
- Focused backend suite covering job layout, exports, artifacts, pins and remote
  provisioning.
- Windows install, startup and uninstall smoke test.
