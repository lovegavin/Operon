# Operon 5.3.0 targeted installed-package acceptance

Do not publish. Record the exact candidate ZIP and Setup hashes before testing.
Use an independent installation and profile; preserve all prior baseline files,
provider wheels, system interpreters, shortcuts and environment registrations.

1. Double-click Setup, install, and open Studio through its actual shortcut.
   Confirm the installed version and owned management interpreter in the logs.
2. Import/create a tiny connected numerical route with fixed parameters. Use the
   ordinary canvas Run control (not only the advanced Plan panel). Select the
   prepared scientific Python and complete explicit preparation. Check that
   logs, results and the recorded memory budget are available.
3. Export the SAME canvas with its ordinary portable-export entry. Do not supply
   a hand-written manifest. Confirm code/resources/parameters/environments are
   collected. Export again without changing dependencies and confirm the
   generation is reused rather than resealing its dependency files.
4. Move/copy the exported package to a different directory, including spaces.
   Set its input paths to synthetic data there. Remove developer PYTHONPATH and
   Operon environment overrides; invoke its own `run.cmd`. Check scientific
   output, frozen parameters and the saved memory policy. Do not substitute an
   installed Operon CLI for the exported launcher.
5. Make one invalid input/parameter change and confirm a useful validation error,
   no duplicate run, and no silent fallback to the old execution path.
6. Close, reopen using the shortcut, verify the saved route/settings and plan
   history. Close normally and record exit timing/code. Uninstall only this
   candidate and compare old baselines. Do not rerun unrelated scientific suites.

If preparation is slow, keep the log, phase and elapsed time. Never label a
background package probe as a successful scientific run. Record skipped items.

Linux acceptance uses the actual server ZIP/wheel in an independent prefix.
Verify system Python and Conda route capture, an external tool in the selected
environment, moved standalone execution, memory/frozen parameters and package
reuse. Record any local official-runtime mirror used to work around network
download failures. Source-only tests do not replace a final-package smoke check.
