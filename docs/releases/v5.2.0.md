# Operon Studio 5.2.0 — candidate under validation

This application release integrates canonical RunPlans, explicitly bound immutable
environments, multi-language execution/export and bounded task/result services.
Operator-library sources and versions are not changed by this release.

## Execution and desktop integration

- The same plan compiler and host-pool authority serve desktop, CLI, API and MCP.
- Frozen workflow values remain independent of library defaults.
- Environment selection verifies compatible prepared generations; preparation is
  explicit. Installing the application does not install every scientific dependency.
- Configured storage browsing uses bounded listings/previews. A browse grant does
  not silently grant execution access or authorize downloading a server dataset.
- Durable desktop submission records retain the original request key after an
  uncertain response; retries must not launch duplicate work.
- Committed artifacts are opened through owned artifact/file identities. Active
  HTML/SVG content must not become trusted application-origin content.
- Portable plans use the same execution kernel and target-native environments.
  Windows R requires an explicitly selected supported physical work directory.

## Retained upstream fixes

Selected 5.1.10–5.1.17 application fixes are retained: installed library layout,
scoped remote dependency preparation, task event paths, result-file access,
direct program upload, missing editable-seed handling and frontend version checks.
An upgrade must not delete previous environments before a replacement is verified,
or remove another deployer's live ownership record merely because force was used.

## Experimental capabilities

Multi-host SSH placement, cross-host failover/transfer and Slurm are **experimental**.
No second compute node or Slurm installation was available for qualification.
They require explicit configuration and are not prerequisites of the default
single-host desktop/server workflows. PostgreSQL repository tests and one-host
RPC tests do not establish distributed failover or real scheduler acceptance.

## Release gate

This document does not assert final-package acceptance. Final Windows Setup and
Linux server archives must be checked from their exact delivered bytes, with
checksums, environment identity, desktop/CLI execution and shutdown evidence.
See the candidate's `FORWARD_TO_TESTER.txt` and the final acceptance ledger.
