prefix with its own Python 3.13 environment. Installed CLI checks exercised
branched YAML, frozen values, explicit environment preparation, missing dependency
rejection, retained logs, stable request reuse after service restart and worker
failure reporting. The older acceptance harness was adapted to the current
version and the task's recorded output directory; the application was not patched
for these checks.

The installed RunPlan CLI compiled and ran the prepared two-stage fixture through
the shared pool, deduplicated its request, and exported a target-native package.

and its environment leases released. Server handshake document reuse and
reinstallation preserved the workspace, server identity and previous interpreter.

RC1 is therefore not qualified for publication. The candidate correction uses
the existing JobService output resolver; final corrected-package checks remain
required. Windows RC1 interaction is in progress, and will be followed by an
update check against the corrected candidate.

## Explicit boundaries

- Only single-host execution is qualified by the existing real scientific tests.
  Multi-host placement and Slurm remain experimental.
- Configured-file versions are metadata checks, not immutable file snapshots.
  Portable relocation of these machine-specific versions is explicitly rejected;
  content-verified portable input bindings remain a separate path.
- New RunPlan artifacts support local original-file opening/saving. Remote full
  transfer and native specialist-viewer integration are not claimed for this path.
- The application-only Linux package does not install or replace an operator
  library. Tests must record any independently installed library identity.
- Exact Setup/server package hashes, final-machine observations and closure
  evidence must be appended after installation acceptance, before publication.
