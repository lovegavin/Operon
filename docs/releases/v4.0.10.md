# Operon Studio 4.0.10

Application 4.0.10 keeps the bundled operator library **8.0.3** and the wire
protocol v3 / SDK 3.7 unchanged. It corrects the remote pin refresh that 4.0.9
did not complete, tightens Windows installation and removal, and retains the
shared-pool upgrade fix.

## Installer location and removal

- Setup uses the exact folder selected by the user. It no longer appends a
  second `Operon Studio` folder or an automatic `-2` suffix.
- If the selected folder already contains an Operon installation without a
  current receipt, non-forced installation stops and asks for **强制重装**.
  Forced reinstall cleans the same root and installs there again.
- The installation receipt records its root. The root uninstaller reads that
  record, cleans the root except `workspace`, removes registrations and
  shortcuts, and then removes itself.
- Unrelated files are preserved when installing into a folder that is not an
  Operon root. A genuine name conflict is reported instead of being renamed.

## Remote pin refresh

- A submission targeting a remote server now removes plugin-lock entries copied
  from an older canvas before preparing the graph.
- The selected host resolves implementations against its own catalog; local runs
  still retain their original pins as evidence.
- 4.0.9 only skipped re-applying the old pins, so the stale entry still reached
  readiness. 4.0.10 removes it before local preparation.

## Shared-pool upgrade

- A forced server upgrade closes all existing workspace sessions before the new
  daemon registers.
- Registration also prunes sessions whose owner process has exited, so a
  workspace left by a killed 4.0.4 process no longer blocks the new server.
- A normal upgrade still aborts on active work without closing live clients.

## Remote status

- MCP `operon_remote_status` reads `GET /api/remote/summary`, returning build and
  library-check facts instead of the full catalog payload.

## Verification

- New stale-remote-pin regression test passed.
- `tests/test_application_engine_requests.py` and
  `tests/test_pool_service.py`: 24 passed in 82.70 s.
- Shared-pool focused tests: 3 passed; pool + remote upgrade: 27 passed;
  managed pool + provisioning + retirement: 32 passed, 3 skipped.
- Installer build: 0 warnings, 0 errors. Windows exact-root, forced-reinstall and
  uninstall checks are recorded in the release acceptance notes.
- No frontend code changed. No full Windows Python suite was run.

## Known gaps

- OpenMM/PDBFixer resolution still depends on a compatible server package source;
  the operators remain unusable when only OpenMM 8.1.1 is available.
- Intermediate artifacts, duplicate default export names, local staging UX and
  broad output-contract axes remain on the report follow-up list.
