# Operon Studio 4.1.9

Released 2026-11-13. Ships Operon Operator Library **8.0.7**; protocol 3 and SDK
3.7 are unchanged.

This release fixes the application-side findings from the 4.1.8 field reports.
The two operator-algorithm findings (`interface_alanine_scan` scanning only the
target side, and non-reproducible MM/GBSA values across copies) belong to the
operator library and require Library 8.0.8; they are not changed here.

## Fixed

- **Exported tables are readable over MCP.** `operon_artifact_table` and
  `operon_artifacts(preview=true)` now parse `.csv`, `.tsv` and `.txt` exports and
  return columns, rows, row labels, `total`, `offset` and `limit`, instead of only
  file metadata. This also covers exported files produced inside composite and
  remote jobs, because the execution layer no longer drops pagination arguments.
- **Pagination is honored end to end.** `offset`/`limit` reach the job service for
  both local and SSH stages; tensors keep the 1000-row cap, tables default to 20
  rows in preview and up to 1000 on request.
- **Stale pins self-heal.** Before a local prepare, pins whose bundled
  implementation is no longer installed are refreshed from the current library;
  each replacement is recorded in `runtime.pin_migrations`. Wheel pins are never
  replaced. Old canvases no longer fail with
  `pinned implementation is unavailable`.
- **`operon_job(wait_seconds=...)` returns instead of timing out.** The internal
  wait is capped at 30 seconds, below the MCP host timeout, and a closed window
  returns `status: running` with `wait_timed_out: true`.
- **`setuptools` bootstrap for isolated environments.** Every environment now
  installs `setuptools>=68,<81` and `wheel` before requirements, including
  environments that share the host interpreter, so `pkg_resources` is available
  to PDBFixer. The receipt records the new bootstrap string.
- **Export operators run out of the box.** The bundled CPU runtime now ships
  `h5py>=3.8` and `biopython>=1.81`, the declared dependencies of
  `export_results`. Previously a local export graph was blocked at readiness
  with `h5py>=3.8: not installed` even though the export itself only needs
  NumPy.
- **Environment repair documentation** now uses `<install root>/environments`
  (the persistent location introduced in 4.1.8) and documents the recovery steps
  and progress/error file locations.
- **Remote deployment works from an installed runtime.** The desktop imports
  `operon` from the bundled runtime's `site-packages`, so the installer previously
  treated site-packages as the application tree and failed with
  `FileNotFoundError`. `operon.remote.provision` now resolves the version
  directory through `code_root()`, and a regression test covers both the shipped
  tree and the site-packages case.

## Compatibility and upgrade

- Application 4.1.9 accepts operator libraries **8.0.6 and newer**; the bundled
  library is 8.0.7 (1,063 operators, 108 Readers, 1,171 descriptors, 7 packages,
  79 routes).
- Upgrading keeps `<install root>/workspace` and
  `<install root>/environments`; previous version files are removed.
- Existing workflows keep their parameter values. Pins that still resolve are
  untouched; only unavailable bundled pins are refreshed, and the migration is
  recorded.

## Verification

- `tests/test_artifact_csv_preview.py`, `tests/test_builtin_pins.py`: 30 passed.
- Focused Python, frontend and Windows install/uninstall evidence is recorded in
  `VERIFICATION.json`, `CI-RESULTS.json` and `ACCEPTANCE.md` of the release.

## Known limits

- Local-origin HTTP artifact downloads still require the `context` capability;
  MCP reads table content through `operon_artifact_table`, which needs no token.
- Raw tensor artifacts are still not retained next to an export node's file
  output; run the data-only graph when the numeric artifact is required.
- Library 8.0.8 is required for binder-side alanine scanning and for MM/GBSA
  reproducibility across binding-site copies.

## Next

- Planned for 4.2.0: a task-folder workspace layout. `workspace/` gains one
  folder per dataset, with `input/` for the raw data and the remaining space
  for that dataset's analysis results; `.studio` stays internal application
  state. Existing documents keep their explicit `base_dir` and are not moved
  silently.
