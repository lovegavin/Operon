# Operon Studio 4.2.3

Patch release for route archive imports.

## Fixes

- **Route archives no longer rewrite unprovable pins.** `POST /api/routes/import-archive` applies
  only replacements proven by the installed library (`operon.library_pins.replacements`: the stored
  `code_sha` must equal the source recorded for that provider, the package and version must match,
  and the rebuilt wheel digest must match the provider receipt). Proven changes are reported in
  `pin_migrations`; a pin that cannot be proven is rejected with an explicit error naming the
  operator and its stored `code_sha` instead of being changed. Importing a route never repairs a
  library whose published artifacts disagree with each other.
- **Pin regression test follows the 4.2 task layout.** `tests/test_builtin_pins.py` now reads run
  events from the job's `output_dir` instead of the pre-4.2 `jobs/<id>/output` path.

## Operator library

This release ships with **Operator Library 8.0.9** and requires **8.0.9 or newer**. Library
descriptors are unchanged from 4.2.2.

## Compatibility

- Workflows, task folders and artifacts are unchanged from 4.2.2.
- Routes whose pins are still installed import unchanged. Routes whose pins were produced by a
  different, provably reconstructed library build are migrated and reported. Everything else is an
  explicit failure.
