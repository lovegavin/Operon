# Operon Studio 4.0.3

Operon Studio 4.0.3 makes remote server replacement recover from stale servers
and removes the manual MCP step from uninstall.

## Remote server upgrade

- A normal upgrade retires idle old servers and shared pools before uploading
  the new build.
- If an old server still has active tasks, the upgrade stops without changing
  the managed server files.
- **强制升级服务端** cancels active jobs through the old server control socket,
  retires its sessions, stops its shared pool, and then installs the new build.
  The desktop asks for confirmation before starting.
- The force path reports which old servers and pools were stopped, or which one
  could not be stopped.

## Windows uninstall

- The uninstaller asks the local bridge to disconnect every connected MCP client
  before terminating Operon/Python processes.
- The "disconnect DSH/MCP first" warning is gone. The force-uninstall
  confirmation remains.
- Quiet uninstalls perform the same MCP disconnect step.

## Windows reinstall

- If the target directory already contains Operon Studio, Setup asks before
  replacing it.
- A normal reinstall closes the old version and refuses to continue while its
  local or remote tasks are still active.
- **强制重装** terminates the old processes and removes the old version files;
  profiles, workspace data, routes, results, and job records are preserved.
- A fresh profile still uses `<install root>/workspace`; an old 4.0.x workspace
  under `%USERPROFILE%` is not migrated automatically.
