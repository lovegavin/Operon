Operon Studio Experimental

Starting the owned backend and waiting for authenticated readiness.

The main Operon window opens only after the owned backend reports its exact loopback origin. This local diagnostics window has no host capability and cannot invoke desktop commands.

What happens next

  • The owned backend is started asynchronously; the native shell does not block the UI thread.
  • On readiness, the main window loads the owned root URL and the bridge installs one runtime capability for that exact origin and window.
  • On failure, this window remains visible with the diagnostic message and log location. The backend is not restarted automatically.

Exit

Use Quit Operon from the native menu or the tray menu. Closing this window also requests a full exit. The host never silently cancels running scientific jobs; a pending-job confirmation is shown when the main UI is ready.

Logs

Logs are written under the configured experimental profile's logs directory. The native menu's Open Logs item and the main UI's diagnostics action open only that fixed directory.
